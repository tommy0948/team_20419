# ⚔️ Slime Hunter 2D - 프로젝트 요구사항 명세서 및 개요

본 문서는 Unity 엔진을 사용하여 개발하는 **2D 탑뷰 액션 게임 'Slime Hunter 2D'**의 프로젝트 요구사항 명세서 및 기획 개요를 담고 있습니다. 오픈소스 에셋 활용 정보 및 유사 게임들과의 비교 분석을 포함하고 있어 개발 진행 시 가이드라인으로 활용할 수 있습니다.

---

## 1. 프로젝트 개요 (Project Overview)
- **게임명:** Slime Hunter 2D (가제)
- **장르:** 2D 탑뷰 액션 / 아케이드 (Top-down Action)
- **개발 환경:** Unity 2D Core (추천 버전: 2022.3 LTS 이상)
- **타겟 플랫폼:** PC (Windows / Mac)
- **핵심 루프:** 플레이어가 `W`, `A`, `S`, `D` 키로 이동하며 사방에서 몰려오는 슬라임을 처치하고 점수(Score)를 획득하는 직관적이고 직관적인 액션 루프.

## 3. 시스템 및 기능 요구사항 (System Requirements)

### 3.1. 플레이어 시스템 (Player System)
- **이동 조작:**
  - 키보드 `W`(상), `A`(좌), `S`(하), `D`(우) 키 입력을 통해 8방향으로 이동할 수 있어야 한다.
  - 대각선 이동 시 속도가 빨라지지 않도록 입력 벡터를 정규화(Normalize) 처리한다.
- **애니메이션 및 방향 전환:**
  - 이동 방향에 따라 캐릭터 스프라이트가 좌/우로 반전(`SpriteRenderer.flipX`)되거나 상/하/좌/우 애니메이션이 전환되어야 한다.
- **공격 매커니즘:**
  - 마우스 좌클릭 또는 `Spacebar` 키를 입력하면 공격 애니메이션이 재생되며, 무기 휘두르기 범위에 충돌 영역(Collider2D - Trigger)이 활성화된다.
- **상태 관리:**
  - 플레이어는 체력(HP)을 가지며, 슬라임의 본체와 충돌 시 무적 시간(예: 0.5초)과 함께 HP가 감소한다. HP가 0이 되면 게임 오버 화면으로 전환된다.

### 3.2. 적 시스템 - 슬라임 AI (Enemy System)
- **스폰 (Spawn):**
  - 게임 시작 후 일정 주기마다 화면 밖 또는 지정된 스폰 포인트에서 슬라임이 지속적으로 생성된다.
- **AI 행동 패턴:**
  - **배회 (Patrol):** 플레이어가 일정 거리 밖에 있을 때는 무작위 방향으로 느리게 배회한다.
  - **추적 (Chase):** 플레이어가 슬라임의 '인식 반경' 안으로 들어오면 플레이어의 위치 좌표를 실시간으로 추적하여 다가온다.
- **피격 및 소멸:**
  - 플레이어의 공격 콜라이더와 충돌하면 슬라임의 HP가 감소하고 피격 이펙트(붉은색 깜빡임 등)가 발생한다.
  - HP가 0 이하가 되면 소멸 애니메이션과 함께 맵에서 제거(`Destroy`)된다.

### 3.3. UI 및 게임 흐름 (UI & Game Flow)
- **인게임 UI:**
  - 화면 상단: 플레이어의 현재 점수(Score)를 실시간 텍스트로 표시.
  - 화면 좌측 상단: 플레이어의 현재 체력을 시각적으로 보여주는 HP 바(Slider) 배치.
- **게임 흐름 관리:**
  - 슬라임을 처치할 때마다 점수가 1점씩 누적된다.
  - 플레이어 사망 시 `Game Over` 텍스트와 함께 최종 점수가 표시되며, '다시 시작(Restart)' 버튼을 누를 수 있는 UI 팝업이 노출된다.

## 5. 기술적 구현 고려사항 (Technical Notes)
1. **물리(Physics) 처리:** - 2D 탑뷰 게임이므로 `Rigidbody2D`의 `Gravity Scale`은 반드시 `0`으로 설정하여 바닥으로 추락하지 않도록 합니다.
   - 벽이나 장애물과의 충돌은 `Collision`, 공격 판정은 `Trigger`를 사용하여 물리 연산의 효율성을 높입니다.
2. **카메라 렌더링:**
   - 카메라는 `Orthographic` 모드로 설정하고, 플레이어를 부드럽게 추락하는 `Lerp` 또는 `Cinemachine 2D Virtual Camera`를 활용하여 고정 추적합니다.
3. **성능 최적화 (추후 확장 시):**
   - 슬라임이 동시에 대량으로 스폰될 경우 인스턴스 생성/삭제 부하를 줄이기 위해 **오브젝트 풀링(Object Pooling)** 시스템 도입을 고려합니다.
